# project-optimization · 定位说明

> 本族是**复盘与提案层**：收「复盘 + 调研实证 + 优化提案」，经用户定案后回写 `docs/project-implement/` 对应章节，**不代改设计**；定案后的执行过程落 `docs/project-progress/` 对应里程碑卷。

## 使用规约

1. **触发**：每里程碑收官当日产出复盘提案（阶段衔接机制，见 `docs/project-progress/PROJECT-PROGRESS.md` §3.4）；重大横向议题可随时立专项（如安全加固、性能专项）。
2. **复盘提案骨架**：现状差距定级 → 优化点清单（P0/P1/P2）→ 否决分析（每条否决**必须带重估触发条件**）→ 下一阶段批次建议（价值×确定性÷成本 排序）。
3. **定案联动**：用户拍板后——设计变更回写 implement 对应章（版本递增+修订注记）；批次建议落下一 M 卷 §3 批次规划（标注「经复盘定案」）；本族文档头部登记定案记录。
4. **边界**：实现细节不进本族（进 progress 卷）；性能调优的「为什么/参数定案」以设计章版本+门禁读数落 implement/progress，本族只留提案与依据。
