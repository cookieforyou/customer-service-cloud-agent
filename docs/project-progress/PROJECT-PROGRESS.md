## 3. 推进纪律（借鉴姊妹项目 kb-rag-agent 方法论，2026-09-20 定稿）

1. **功能批四件套**：① 代码+测试（全绿）→ ② 文档回写（设计章修订注记版本递增；涉架构事实同步 AGENTS.md）→ ③ 需用户验证的登记用户侧清单 → ④ 一功能一提交。提交信息带锚点：`feat(域): M<N>批<y> 摘要——要点（坑#xx / 回写《NN》vN.M）`。
2. **状态行格式**（追加至 00 卷）：`> **日期 状态(M<N> 批<y>)**: 交付要点 + 实证读数（测试计数/指标）+ 回写锚点（章节版本号）+ 下一步`。状态行只放「读数+结论+指针」，过程细节写任务行。
3. **E2E 热修循环**：用户复跑暴露 → 根因定位（源码级）→ 治法 → 坑位登记（《15-附录》四点联动）→ 设计回写 → 复跑通过销账。热修在 M 卷 §7 按行记录（热修一/二/三…），不留无痕修复。
4. **阶段衔接（复盘成簇）**：每里程碑收官当日产出复盘提案入 `project-optimization`（差距定级 → 优化点 P0/P1/P2 → 否决分析 → 下一阶段批次建议），经用户定案后细化下一 M 卷批次规划；**不代改设计**。
5. **决策纪律**：里程碑内重大技术决策在 M 卷 §5 用「选项表（形态/依据，推荐加粗置首）+ 定案记录（日期 拍板人）」落档；spike 判负必须留档回落路径；被否决方案必须带**重估触发条件**。
6. **上下文经济学**：大卷勿整读整写（按任务行定位）；单卷超 20KB 即拆分（状态行收归 00 卷、任务行归 M 卷）；大范围探索委派只读子代理。
7. **分支纪律**：默认 main 小步快跑；涉用户 E2E 复跑窗口的大批次开 `m<N>-b<y>-<slug>` 分支，销账合入（防复跑窗口基线漂移）。
