## INF-2 Casdoor 应用注册（清单已随 M0批3 交付）

- **目的**：坐席/服务/管理员三类身份走 Casdoor JWT（与 KB 服务同源身份体系）；**访客身份不经 Casdoor**（平台自签 `urn:csca:visitor`，站点 appKey+HMAC 验签换发——《11》§7 v1.2.0）。
- **注册字段**（在既有 Casdoor 中新建应用 `csca`）：
  1. 组织与应用：应用名 `csca`，记下 client_id/client_secret（服务身份 client_credentials 用）；
  2. Token 签名算法：**RS256**（本平台按公钥/JWKS 校验，不支持 HS256 共享密钥）；
  3. Token claims 开启：`sub`（用户名/ID）、用户自定义字段 `owner`（租户 ID）、`roles`（角色集合）；建议 audience=`csca`；
  4. 坐席测试账号 ≥3（M2 验证并发分配用），赋予角色 `AGENT`；管理员账号 1 个（角色 `ADMIN`）；
  5. 回填环境变量（部署 .env，M0批5 部署形态用）：`CS_AUTH_CASDOOR_ISSUER`（Casdoor 的 issuer，通常 `https://<casdoor-host>/<org>` 形态）、`CS_AUTH_CASDOOR_JWKS`（JWKS 端点，通常 `https://<casdoor-host>/.well-known/jwks.json`——以实际版本为准）。
- **验证**：任取一个坐席账号签发 JWT（Casdoor API 或密码模式），回传 token 与 `CS_AUTH_CASDOOR_ISSUER/JWKS` 值，机器侧核验 claims 形态（sub/owner/roles）后销账。
- **预期回传**：issuer/JWKS 两个 URL 值 + 一个样例坐席 token（脱敏可）+ 一条 claims 截图读数。

> **✅ 销账记录（2026-09-20 回传核验）**：回传物料（token + payload 解析）按纪律 9 落 `logs/` 临时区，敏感值不入文档不入仓库。实测读数（openssl + JWKS 独立验签通过，kid=cert-built-in）：issuer = 私有部署 Casdoor host（真实值仅本地 `.env`，不入仓库；与 OIDC discovery 一致）；`sub` = 用户 UUID、顶层 `name` = 用户名、`owner` = 组织即租户（csca_tenant_001）、`roles` = [AGENT]（**对象数组**，角色名取元素内 `name`）、`aud` = `{client_id}-org-{org}`（校验暂未启用）、RS256、access-token TTL 7 天。三处契约修正落码（坑#19，《11》§7 v1.3.0）：① 资源服务器转换器改为 `roles[].name` 提取（原按字符串集合处理会产出垃圾 authority），单测 4 项镜像真实 payload 钉死；② JWKS 端点实测为 `/.well-known/jwks`（**无 `.json` 后缀**，带后缀返回空 keys，注册清单第 5 条的惯常形态在当前 Casdoor 版本不成立）；③ `/api/jwt/public-key`、`/api/jwks` 需管理鉴权不可匿名用。issuer/JWKS 配置形态见 `.env.example` 模板（**占位域名**，私有部署地址不入仓库），真实值仅本地 `.env`（gitignore 排除）。
> **✅ 补齐记录（2026-09-20 二次回传）**：坐席测试账号已补齐 3 个（agent_001 / agent_002 / agent_003，角色 AGENT）——M2 并发分配验证条件就绪，遗留小项关闭。

- **回滚**：删除应用即可。
