## INF-1 监控栈部署

- **目的**：M0 观测出数的前提（trace→Jaeger、指标→Prometheus/Grafana）。
- **前置 ⚠️**：与同 ECS 既有栈（KB 服务监控栈 9092/3001/16687/4319 已占用，姊妹项目坑#10）端口冲突——本平台 compose 将另用端口段（资产交付时给端口分配表）；镜像全部钉版（坑#06，禁 latest）。
- **步骤**：待 M0 批1 交付 compose 资产后照做（含 `docker compose up -d`、健康检查命令）。
- **预期回传**：Prometheus targets 全 UP 截图读数；Jaeger UI 可访问。
- **回滚**：`docker compose down`（独立栈，无副作用）。

## INF-2 Casdoor 应用注册

- **目的**：平台三类身份（访客/坐席/服务）与 JWT 签发，服务间调 KB 同源鉴权。
- **前置 ⚠️**：audience 与 KB 服务现有应用区分；JWT claims 需含 `owner`（租户）与 `sub`。
- **步骤**：待 M0 批3 交付注册字段清单（redirect/callback/claims 映射）后照做。
- **预期回传**：client_id/secret 配置到位（不入库，仅 .env）；测试三类 token 可签发。
- **回滚**：删除应用即可。

## INF-3 KB 服务联调凭据

- **目的**：M1 知识通道（MCP 主/A2A 备）联调。
- **前置 ⚠️**：MCP 限流 120 次/60s/租户——联调用独立测试租户，勿与 KB 生产租户混用。
- **步骤**：待 M1 批4 交付（含 `POST /mcp` initialize 探活、`/.well-known/agent-card.json` 拉取验证）。
- **预期回传**：探活成功读数；一次 `search` 调用返回非空（或记录空召回属正常）。
- **回滚**：吊销凭据。

## INF-4 阿里云内容安全开通

- **目的**：M1 护栏链输入/输出送审（`llm_query_moderation`/`llm_response_moderation`，经 TextModerationPlus）。
- **前置 ⚠️**：开通区域与 AK 最小授权；流式分段送审按段计费，先按测试量小额开通。
- **步骤**：待 M1 批5 交付接入配置模板（Service 参数/region/AK 注入位）。
- **预期回传**：一条样例文本送审返回 riskLevel 读数。
- **回滚**：停用服务。

## INF-5 Langfuse 栈部署

- **目的**：M1 质量运营（trace/scores/prompt 管理/标注队列）。
- **前置 ⚠️**：v3 架构四件套（PG/ClickHouse/Redis/MinIO）——ClickHouse 与 MinIO 为新增组件，预留 ~4GB 内存；compose 单机形态仅供当前规模，容量预案见《14》风险表。
- **步骤**：待 M1 批6 交付 compose 资产（含 pk/sk 生成指引、OTLP 端点连通自检 curl）。
- **预期回传**：`/api/public/otel/v1/traces` 探活 200；UI 可登录。
- **回滚**：`docker compose down -v`（独立数据卷）。
